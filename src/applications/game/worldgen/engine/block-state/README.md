# engine/block-state

Block state knowledge for worldgen, recorded from the real Minecraft 1.20.6 classes rather than written from
memory, so heightmaps, block predicates and `canSurvive` behave like the game.

| Export | Mirrors |
| --- | --- |
| `BlockStateCatalog` (`info`, `normalize`, `propertiesOf`, `withProperty`, `forPalette`) | `BlockBehaviour.BlockStateBase`: `isAir`, `blocksMotion`, `isSolid`, `canBeReplaced`, `getFluidState`, `isFaceSturdy`, `liquid`; `LeavesBlock` / `DoublePlantBlock`; `BlockState.CODEC` defaults |
| `SurvivalRules.canSurvive(state, level, x, y, z)` | `BlockState.canSurvive(LevelReader, BlockPos)` |
| `BlockTagIndex` | `BlockState.is(TagKey<Block>)` over the datapack loader's flattened block tags |

- `block-state-table.generated.ts` is generated by `generate-block-state-table.node.ts` from
  `fixtures/block-state-reference.json.gz`, which `../features/fixtures/FeaturesReference.java` records for all 1060
  registered blocks: default-state flags, every non-waterlogged state whose flags differ, sturdy faces of the default
  state, and a `canSurvive` probe (one neighbor below / above / north, everything else air, plus water beside the
  block below and darkness) for the default state and its attachment variants.
- Unknown block names: strict catalogs (tests) throw `UnknownBlockError`; lenient catalogs (runtime) classify them as
  a full solid block and count them in `unknownBlockCounts`.
- Approximations, by design: survival neighbors are matched by block name using their default state; sturdy faces
  are those of the default state; only the probed neighbor directions are consulted, except for the multi-neighbor
  rules ported by hand (`CactusBlock`, `SugarCaneBlock` water, `TallSeagrassBlock` water, `DoublePlantBlock` upper
  half, wall-attached `facing` rotation). Waterlogged states (`waterlogged=true`) hold a water source.
